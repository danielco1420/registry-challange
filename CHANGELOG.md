# Changelog

All notable changes to this project are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- Multi-stage `Dockerfile` (Node 22 Alpine): a build stage with full devDependencies compiling the app, and a minimal production runtime stage with prod-only dependencies, no `.env` or dev tooling baked in, running as the image's non-root `node` user over root-owned app files, exposing port 3000 and healthchecking `/api/health`. `.dockerignore` keeps `node_modules`, `.env*` (at any depth), `.git`, `.claude` and docs out of the build context. `docker-compose.yml` (Compose v2.24.0+) builds the image, maps port 3000, and optionally loads `.env` via `env_file` (missing file is fine). README documents both `docker build`/`docker run` and `docker compose up`.
- Docker Hub API map with live-verified endpoints, params, and response fields (`docs/API.md`).
- Design questionnaire covering stack, data, routing, UI, product, quality and security decisions.
- Risk register with mitigations (`docs/RISKS.md`).
- Architecture stub, project summary skeleton, and ADR-0001 (backend proxy, because Docker Hub has no CORS).
- Contribution rules, AI assistant guides (`CLAUDE.md`, `AGENTS.md`), GitHub templates, Dependabot, security policy, and editor/git config.
- Answers to every design questionnaire question; ADR-0002 (React Router v7 single app) and ADR-0003 (server cache and upstream failure handling).
- React Router v7 app (framework mode, SSR) with TypeScript strict, pnpm and Node 22; placeholder home page and `/api/health`.
- ESLint (typescript-eslint, React Hooks, jsx-a11y) and Prettier, with `pnpm lint`, `pnpm lint:fix`, `pnpm format` and `pnpm format:check`.
- Husky git hooks: pre-commit runs lint-staged, commit-msg runs commitlint (Conventional Commits, types from `CONTRIBUTING.md`).
- Valibot schemas for every route param (`namespace`, `repo`, `tag`, `q`, `page`, `pageSize`, `sort`, `badge`, `ordering`, tag filter) and a helper that turns a failed parse into a `400` JSON error (`app/lib/params.ts`, `app/lib/validate.ts`). A repeated query key keeps its first occurrence, even when it's empty (e.g. `?sort=&sort=stars` leaves `sort` missing).
- Table-driven param cases (`app/lib/params.cases.ts`), run against the schemas by `pnpm test` (`app/lib/params.test.ts`).
- Typed env config (`app/server/config.server.ts`), validated with Valibot at startup. Invalid values, including `UPSTREAM_BUDGET_PER_MIN` above 150, stop the server with a clear message.
- Docker Hub upstream client (`app/server/dockerhub.server.ts`): builds URLs only from typed, validated requests; `UPSTREAM_TIMEOUT_MS` timeout; descriptive User-Agent; one retry on 429/5xx/timeout/non-JSON honoring `Retry-After` (or `x-ratelimit-reset` on a 429), failing fast instead when the wait is over 3 s; typed `UpstreamError` (`not_found`, `rate_limited`, `unavailable`, `bad_payload`); responses validated with a caller-supplied Valibot schema. Tests run in `pnpm test`.
- Server-side in-memory cache (`app/server/cache.server.ts`): LRU bounded by `CACHE_MAX_ENTRIES`, single-flight per key, stale-while-revalidate with one background refresh, ±10% TTL jitter, and a `HIT`/`MISS`/`STALE` status plus entry age for `X-Cache` headers. Not wired to routes yet.
- Per-client rate limiter (`app/server/rateLimit.server.ts`): `RATE_LIMIT_MAX` requests per `RATE_LIMIT_WINDOW_MS` per client IP, answering 429 with `Retry-After`, with bounded memory. Ready for `/api/*` routes and page loaders to call; not wired into them yet.
- `TRUST_PROXY_HOPS` env var (default `0`): how many reverse proxies' `X-Forwarded-For` entries to trust when resolving the client IP. With the default the client IP is unknown, so the per-client limit doesn't apply until a deployment sets it.
- Proxy-wide upstream budget (`app/server/budget.server.ts`): at most `UPSTREAM_BUDGET_PER_MIN` Docker Hub attempts in any 60 s, retries included; with no slot left, nothing is sent (`UpstreamError` kind `budget_exhausted`).
- `getCached(key, ttlSeconds, fetcher)` facade (`app/server/upstream.server.ts`) wiring the cache, the upstream client and the budget, with a `degraded` flag for the UI banner. When the budget is spent or Docker Hub is failing it serves stale data (`200`, `X-Cache: STALE`, `Cache-Control: no-store`) or, with nothing cached, a `503` JSON error with `Retry-After` and `Cache-Control: no-store`. Not wired to routes yet (T13).
- Pure formatting helpers in `app/lib`: `pullCommand`/`pullByDigest` (`app/lib/pull-command.ts`, strip the `library/` namespace per CLAUDE.md hard rule 6), and `formatRelativeDate`/`formatCompactNumber`/`formatSize` (`app/lib/format.ts`), all via `Intl` (`RelativeTimeFormat`, `NumberFormat`, `DateTimeFormat`); `formatSize` returns `"—"` for zero/unknown size (RISKS.md 4.3), and `formatRelativeDate` returns `"—"` for a missing or unparseable date.
- Test tooling: Vitest with a Node project (`app/**/*.test.ts`) and a jsdom project with Testing Library and jest-dom (`app/**/*.test.tsx`); MSW in both projects, which blocks any unhandled HTTP request or WebSocket to a non-loopback host so tests never reach Docker Hub; a `fixtures/dockerhub/` folder for recorded responses (filled in T08); Playwright (Chromium) with an e2e smoke test against the production build. Scripts: `pnpm test`, `pnpm test:watch`, `pnpm test:coverage` (v8 coverage of `app/server` and `app/lib`, report only, ~80% target) and `pnpm test:e2e`.
- CI (`.github/workflows/ci.yml`): GitHub Actions on every PR to `main` (and on pushes to `main`) with jobs `lint` (ESLint + Prettier check), `typecheck`, `test`, `build`, `audit` (`pnpm audit --audit-level=high`) and `e2e` (Playwright, Chromium). Node from `.nvmrc`, pnpm from `packageManager`, `pnpm install --frozen-lockfile`, pnpm store and Playwright browsers cached; the Playwright report and traces are uploaded after every e2e run that isn't cancelled. Dependabot now also updates the actions used by the local composite action in `.github/actions/`.
- `pnpm-workspace.yaml` with `allowBuilds: { esbuild: false }`, so `pnpm install` on a clean checkout no longer fails with `ERR_PNPM_IGNORED_BUILDS`. esbuild's install script stays off; esbuild still works through its platform package.
- Docker Hub response schemas (`app/server/dockerhub.schemas.server.ts`) for search v4, suggestions, legacy search, repository, tags, single tag, orgs and users, and normalizers (`app/server/normalize.server.ts`) into the `RepoSummary`, `RepoDetails`, `Tag` and `Page<T>` DTOs (`app/lib/dto.ts`): `library` handling, `pulls` + `pullsLabel` from either the `"1B+"` label or the number, missing logo/description/size fallbacks, attestation entries and non-repository search results dropped. `RepoSummary` gains `archived`.
- Search fallback (`app/server/search.server.ts`): when `/api/search/v4` fails its schema, one call to the legacy `/v2/search/repositories/` (new `legacySearch` client endpoint) answers instead, marked `source: "legacy"`. Not used for popular or badge-filtered searches; a sorted search falls back in relevance order.
- Recorded Docker Hub responses in `fixtures/dockerhub/` (popular, search, suggestions, legacy search, nginx, fluent/fluent-bit, a repo without a logo, an archived repo, publishers, a 404), MSW handlers that serve them (`test/msw/dockerhub.ts`), and contract tests for the schemas and normalizers.
- i18n with `react-i18next`/`i18next` (`app/i18n/i18next.ts`): one instance initialized synchronously from bundled resources (`app/i18n/en/common.json`), language fixed to `en`, identical on server and client (no hydration mismatch), wrapped around the app via `I18nextProvider` in `app/root.tsx`. The home route's copy now goes through `t()`/`i18next.t()`, with keys typed against the catalog so a typo fails `pnpm typecheck`. A dev-only `missingKeyHandler` throws on a missing key (logs once per key outside dev), covered by `app/i18n/i18next.test.ts`.
- Security headers on every page and API response (`app/server/securityHeaders.server.ts`): a nonce-based Content Security Policy on HTML pages (`default-src 'self'`, scripts only from our origin or with the per-request nonce, images also from `https://*.cloudfront.net` and `https://www.gravatar.com`, `frame-ancestors 'none'`), a CSP that allows nothing on `/api/*` and `.data` responses, plus `Strict-Transport-Security`, `X-Content-Type-Options: nosniff` and `Referrer-Policy: strict-origin-when-cross-origin`. `pnpm dev` also allows inline styles for Vite's injected CSS. React Router's route middleware is now on (`future.v8_middleware`).
- Docker Hub proxy routes: `GET /api/popular`, `/api/search`, `/api/search/suggestions`, `/api/repos/:ns/:repo`, `/api/repos/:ns/:repo/tags`, `/api/repos/:ns/:repo/tags/:tag` and `/api/publishers/:name` (org, else user). Each applies the per-client rate limit, validates its params (`400`), reads through the server cache and upstream budget, and returns a normalized DTO with `X-Cache`, `Age` and a `Cache-Control` matching its TTL; stale data when Docker Hub is failing, else `503` with `Retry-After`. A missing repository, tag or publisher answers a cached JSON `404` (for tags, also a page past the last one). A write method answers a JSON `405` with `Allow: GET, HEAD`. Search and tags reject `page × pageSize > 1000` with a `400`, since Docker Hub answers `403` past the first 1000 results without sign-in. Any other `/api/*` path answers a JSON `404` and calls nothing upstream. New DTOs `SearchPage` (with `source`) and `Publisher`; errors share one `{ error: { code, message } }` shape.
- Tailwind CSS v4 (`@tailwindcss/vite`) and shadcn/ui (`components.json`, `cn` in `app/lib/utils.ts`, the `Button` primitive in `app/components/ui/button.tsx`). Brand design tokens for light and dark themes in `app/app.css`: neutral grays with a light green accent, dark mode under a `.dark` class on `<html>` (the toggle comes with the app shell). Text (green text included), Button hover fills and focus rings meet WCAG AA in both themes, checked by `app/lib/theme-contrast.test.ts` against the tokens in the stylesheet. The app's wordmark, "Danny's Dockers" with a three-crate mark (`app/components/brand/wordmark.tsx`), heads the placeholder home page. No Docker logo or trademarks.
- App shell around every page (`app/components/layout/app-shell.tsx`, rendered from `Layout` in `app/root.tsx`): a "Skip to main content" link as the first tab stop, a header with the brand link home, a slot for the header search box (filled by the search bar below) and the theme toggle, a `<main>` landmark that takes focus from the skip link, and a footer noting the data comes from Docker Hub and the app isn't affiliated with Docker, Inc. Desktop-first, laid out for 768 px and up. Keyboard focus shows a visible ring in the brand green on links and buttons.
- Loading, empty and error states (`app/components/state/`): `Loading` (spinner with short text), `Empty` (with a required call to action), `ErrorState` (page not found, repository not found, Docker Hub unavailable, too many requests, something went wrong; "Try again" for the last three, "Back to Explore" for all, and "You can try again in N seconds" from `Retry-After`) and `DegradedBanner` (saved data shown when it couldn't be refreshed, because Docker Hub is failing or the upstream budget is spent). All copy goes through i18n and names a next action. A root `ErrorBoundary` maps errors to these states: an unknown URL now gets a "Page not found" page (still a `404`), page loaders turn upstream failures into a `503` "Docker Hub unavailable" state and the per-client limit into a `429` "Too many requests" state with `toPageErrorResponse`, and a missing resource into a cached `404` with `pageNotFound` (`app/server/pageError.server.ts`). The error page's `Retry-After` and `Cache-Control: no-store` reach the document response.
- Shared repository components, ready for the Explore and repository pages: `RepoCard` (`app/components/repo/repo-card.tsx`) shows the logo, name, owner, description ("No description" when empty) and the official / verified badge, and the whole card links to the repository page (`/_/{repo}` for official images, `/r/{ns}/{repo}` otherwise) as a single tab stop. `RepoLogo` loads logos with no referrer, and falls back to the publisher's avatar (looked up through `/api/publishers/:name` only when the logo is missing or broken, once per publisher) and then to initials. `RepoBadge` is built on a new shadcn/ui `Badge` (`app/components/ui/badge.tsx`). `CopyButton` (`app/components/copy/copy-button.tsx`) copies to the clipboard, shows "Copied ✓" for 2 s and announces it to screen readers. When the clipboard isn't available or refuses, it shows the text selected in a read-only input to copy by hand.
- Light / Dark / System theme toggle in the header (`app/components/theme/theme-toggle.tsx`), defaulting to System. The choice is stored in an `HttpOnly`, `SameSite=Lax` `theme` cookie (System deletes it) by the new `POST /theme` action, which validates the value (`400` otherwise) and refuses a cross-origin post (`403`). Behind a TLS-terminating reverse proxy, set the new optional `PUBLIC_ORIGIN` env var so the no-JavaScript form post isn't refused; unset, the check compares against the request URL. The toggle's JavaScript post is still refused there (`400`), since React Router's own `Origin` check runs first and compares against the request URL. The root loader reads the cookie, so the server renders `<html class="dark">` or `class="light"` and the page never flashes the wrong theme. HTML pages now send `Vary: Cookie`. System uses no class and follows the OS through `prefers-color-scheme`, live, with no inline script. The toggle updates optimistically through a fetcher and, without JavaScript, works as a plain form that redirects back to the same page (same-origin paths only, also after dot segments are resolved).
- Repository page at `/r/{ns}/{repo}`, and `/_/{repo}` for official images (`/r/library/{repo}` and its tabs answer a `301` to it, query kept). A header shows the logo, name, owner, description, badge, "Archived", last updated (relative, absolute on hover), pulls and stars, above "Overview | Tags" tabs, each with its own URL. The Overview renders the repository's README as sanitized Markdown (`app/components/markdown/markdown.tsx`): raw HTML is never rendered, only `http(s)`/`mailto` links and `https` images are kept, links get `rel="noopener noreferrer nofollow"`, images are sent no referrer and fit the column, and long lines, code blocks and wide tables wrap or scroll inside the page. A repository without a README gets an empty state pointing to its tags. A missing repository or invalid name shows "Repository not found" (`404`), a Docker Hub outage "Docker Hub unavailable" (`503`), and stale data the degraded banner. The page shares its cache entry with `GET /api/repos/:ns/:repo`. New dependencies: `react-markdown`, `remark-gfm` and `rehype-sanitize`.
- Image search box (`app/components/search/search-bar.tsx`) in the header on every page but Explore, and as a larger box on Explore. It is a plain `GET` form to `/search?q=`, so it works without JavaScript (the results page comes in T23; until then a search lands on "Page not found"). With JavaScript it is a WAI-ARIA combobox: after a 250 ms pause and at least 2 characters it shows suggestions from `/api/search/suggestions`, and picking one opens its repository page (`/_/{repo}` for official images, `/r/{ns}/{repo}` otherwise). Arrow keys move through the list, Enter picks or searches, Escape closes it. Loading, empty and error states show in the list and are announced politely; when suggestions fail, searching still works. Each request is aborted when the query moves on and results are keyed by query, so a late older answer never replaces a newer one (RISKS 4.5). Autocomplete uses `fetch` rather than `useFetcher` ([ADR-0004](docs/adr/0004-autocomplete-with-fetch.md)).
- Recent searches: the last 8 searches (deduplicated ignoring case, most recent first) are kept in `localStorage` and listed when the search box is empty, with a "Clear recent searches" action. Both search boxes share the list, other tabs stay in sync, and when storage is blocked or full the list lives in memory for the page load (`app/lib/storage.ts`, `app/lib/recent-searches.ts`).
- Tags tab on the repository page (`/r/{ns}/{repo}/tags`, `/_/{repo}/tags`): a table of tag, last updated (relative, absolute on hover), size and a `docker pull` command with a Copy button (`library/` left out for official images). Sort by tag (A→Z first) or last updated (newest first, the default) from the column headers, kept in `?ordering=`; filter by name, kept in `?name=` and applied after a 300 ms pause (a plain form without JavaScript). "Load more" adds 50 tags at a time without leaving the page, so repositories with thousands of tags never load whole; past Docker Hub's 1,000-tag limit for anonymous use, a note suggests filtering. Loading, "No tags yet", "No tags match" (with Clear filter), Docker Hub unavailable, rate limited and stale-data states show inside the tab, and a failed "Load more" keeps the tags already shown and offers Try again. The tab shares its cache entries with `GET /api/repos/:ns/:repo/tags`.

### Changed
- `docs/API.md`, `CLAUDE.md` and `AGENTS.md` list the suggestions and single-tag routes in the allowlist; `docs/RISKS.md` statuses updated now that the routes are wired.
- A Docker Hub response that fails its schema now reports where: `UpstreamError` has `issuePath` (e.g. `$.results[3].name`, keys only, never values), also appended to the message.
- `docs/API.md`: documented what the live responses actually contain (v4 `name` and `publisher.name` semantics, `logo_url: {}`, pull-count labels, non-repository search results, archived repos answering 200, reversed tag `ordering`, attestation images, `/v2/users/{org}` redirecting to `/v2/orgs/{org}`), the normalization rules and the search fallback.
- Calling Docker Hub anonymously: removed `DOCKERHUB_PAT` from `.env.example`.
- PRs now merge with merge commits instead of squash.
- Moved the assignment brief from `README.md` to `docs/ASSIGNMENT.md`. `README.md` now describes the project.
- `docs/API.md`: param validation section now states that routes aren't wired to the schemas/helper yet, matching `docs/RISKS.md` 2.2/2.3.
- One test runner: the cache, upstream client, rate limiter and param tests moved from Node's built-in runner and the ad hoc `scripts/check-*.ts` checks to Vitest. The `scripts/` folder and its `.ts` resolve hook are gone.
